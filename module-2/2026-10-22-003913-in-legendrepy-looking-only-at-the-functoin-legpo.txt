● The problem isn't the amount of space. It's that the space is fixed while the
  numbers have different widths.

  end="   " always adds 3 spaces after each entry. A 1-digit entry like 4 then
  takes 4 characters in total, but a 2-digit entry like 12 takes 5. So every
  multi-digit number pushes the rest of its row one character to the right, and
  the columns drift apart. Adding more spaces doesn't fix that, because the
  difference between rows stays the same.

  The fix is to give each entry a fixed-width box and let Python pad it with
  spaces.

  Option 1: a width inside the f-string (most common)

  You can put a format spec after a colon inside the braces. These are general
  examples, not your line:

  print(f"[{7:4}]")    # [   7]   a box 4 wide; numbers line up on the right by 
  default
  print(f"[{42:4}]")   # [  42]
  print(f"[{7:<4}]")   # [7   ]   < lines up on the left
  print(f"[{7:^4}]")   # [ 7  ]   ^ centers

  Each entry now uses exactly 4 characters, whatever its number of digits.
  Numbers lined up on the right are the usual choice for tables, because the
  ones digits sit in one column.

  Option 2: string methods

  str(42).rjust(4) does the same thing as f"{42:4}". It's useful to know, but
  the f-string version is shorter.

  Option 3: pick the width from n (the best version)

  Hard-coding 4 works up to n = 31. At n = 32 the largest entry is 32 × 32 =
  1024, which has 4 digits and fills the box with no space left. A better
  approach is to compute the width from the largest entry in the table, which is
  n × n. Two ways to count its digits:
  - len(str(...))
  - something with math.log10 (and you already import math on line 4)

  You can put a variable inside the format spec with nested braces:
  f"{value:{w}}".
